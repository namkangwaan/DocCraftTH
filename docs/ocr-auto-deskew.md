# OCR Auto-Deskew & Orientation Rectification — design

สถานะ: เฟส 1 (แกนอัลกอริทึมใน `crates/ocr/src/deskew.rs`) เสร็จแล้ว; เฟส 2–5 ยังไม่เริ่ม

## เป้าหมาย
ตรวจความเอียงของหน้าสแกน (ราว 0.2° ถึง ±20° พร้อมการหมุน 90/180/270°) และปรับให้ตรงก่อน OCR
(ไทย CTC และอังกฤษ `ocrs`) โดยไม่ทำลายวรรณยุกต์/สระ (ิ ี ึ ื ุ ู ่ ้ ๊ ๋ ์) ไม่ถูกหลอกด้วยตราครุฑ
ขอบดำของสแกนเนอร์ หรือเส้นจุดไข่ปลาในแบบฟอร์มราชการ และหน้าที่ตรงอยู่แล้วต้องไม่ถูกแตะ

## ค่าเริ่มต้นที่เลือกเอง (รอผู้ใช้ทบทวน)
1. รองรับทั้งสองโหมด: **transient** (เอียงเฉพาะภาพที่ส่งเข้า OCR, ไม่แก้ PDF, กล่องคำถูกแมปกลาง) เป็นค่าเริ่มต้น และ **persistent** (ปรับหน้าถาวร undo ได้ แล้ว OCR) ผู้ใช้เลือกได้
2. เอียงสูงสุด ±20° + หมุน 90/180/270° อัตโนมัติ
3. Deskew อัตโนมัติโดยมี confidence gate (ปิดได้)
4. คงขนาดหน้าเดิม และย่อเนื้อหาเท่าที่จำเป็นให้หมึกที่หมุนแล้วอยู่ในกรอบ (ไม่ตัดข้อความมุมกระดาษ)
5. ฐาน: `chore/sync-upstream-2026-11-21`; push เฉพาะ `origin`

## อัลกอริทึม (เฟส 1 — ทำแล้ว)
- ย่อภาพเฉลี่ยพื้นที่เหลือด้านยาว ≈ 1100 px (A4 300 dpi ก็ใช้ราคาเท่ากัน)
- หมึก = เข้มกว่าค่าเฉลี่ยท้องถิ่นเกินขอบ (Bradley, integral image)
- กำจัดสิ่งที่ไม่ใช่ตัวอักษร: ขอบหน้า 3% + ขอบดำสแกนเนอร์ (ขยายตามความเข้ม), connected component
  ที่ใหญ่ทั้งสองทิศ (ตราครุฑ/กรอบ), เส้นตั้งยาว, และก้อนใหญ่ที่แตะขอบ — **เก็บ** เส้นจุดไข่ปลา/เส้นนอนไว้
  เพราะช่วยให้ค่าแม่นขึ้น
- ค้นหา 3 ชั้น: ±20° ทีละ 1° → ±1.5° ทีละ 0.2° → ±0.3° ทีละ 0.05° + parabolic interpolation
  คะแนน = Σ(Δ bin)² ของฮิสโตแกรมแถวหลังเฉือน (splat เชิงเส้น)
- แกนหมุน 90/270°: เทียบคะแนนดีที่สุดของหมึกตั้งตรง vs หมุน 90° (ทนต่อความเอียง) ต้องชนะ ×1.3
- 0° vs 180°: ใช้ bottom-heaviness ของแถวบรรทัด ซึ่งเป็นสมมติฐานแบบละติน **ไม่เชื่อถือกับภาษาไทย**
  จึงยอมพลิกเฉพาะเมื่อมาร์จินกว้าง (≥0.08) ที่เหลือมอบให้เฟส 3: เทียบคะแนนความมั่นใจ Thai CTC ที่ 0° vs 180°
- Gate: ความเด่น (best−median)/(best+median) ≥ 0.2, |มุม| ≥ 0.2°, และคะแนน > 1.03× คะแนนที่ 0°
- Warp: bilinear (เริ่มต้น) หรือ Catmull-Rom, เติมสีกระดาษ (median ของพิกเซลสว่าง 10%), พิกัดขอบพิกเซล,
  `InverseTransform` f64 แบบแน่นอน (compose กับการหมุน 90° ได้)
- `DeskewReport { detected_deg, applied_deg, confidence, orientation_turns, orientation_confidence }`
  (ฟิลด์สุดท้ายเพิ่มเอง)
- ขีดจำกัด: ภาพขนาดเล็ก < 64 px, หน้าว่าง, หน้ามืด → no-op; ใช้ `OcrImage` ที่ผ่าน `MAX_SIDE`/`MAX_PIXELS`
  แล้ว; ไม่ unsafe/unwrap/panic

## เกณฑ์ยอมรับ และผลที่วัดได้จริง (เฟส 1)
| เกณฑ์ | ผล |
|---|---|
| MAE มุม ≤0.15° (±15°) | 0.007° บนหน้าสังเคราะห์ (±0.3…15°) |
| หน้าตรงไม่ถูกหมุน | 3 ชนิด × มีตรา/ไม่มี + ขอบดำ: ภาพคืนเหมือนเดิมทุก byte |
| ความเร็ว ≤150 ms ต่อ A4 300 dpi (native) | **ผ่าน** บน release (`cargo test --release`, WSL, 2480×3508, 5 รอบ, thread เดียว): มัธยฐาน ~96 ms (ต่ำสุด 92, สูงสุด 110) สำหรับ `analyze`; ก่อนปรับ ~111–134 ms. ปรับโดยให้ refine ละเอียดเฉพาะแกนที่ชนะ (แกนที่แพ้ทำแค่ coarse) + warp bilinear เส้นทางลัดในภาพ. `straighten` ทั้งหมด (วิเคราะห์ + warp ภาพ 8.7 MP) ~330 ms. ตัวเลขนี้ตัวเลขบนเครื่องพัฒนาที่แกว่งได้ ±15% |
| ความเร็ว WASM ≤400 ms | **ผ่าน** วัดจริงใน Node v22 (V8) ด้วย wasm-bindgen-test-runner 0.2.129, ภาพ 2480×3508, 7 รอบ, `analyze` มัธยฐาน **67 ms** (rustc opt-level 3; ต่ำสุด 64, สูงสุด 88) และ **123 ms** (rustc opt-level z แบบเว็บแอปขนาดเล็ก; 122–139); `straighten` ทั้งหมด 362 / 494 ms. ข้อจำกัด: Node ไม่ใช่เบราว์เซอร์ (V8 ใกล้เคียง Chrome, ไม่ใช่ Firefox/Safari), ยังไม่ผ่าน wasm-opt, หน้าทดสอบสังเคราะห์ไม่มีตรา และตัวเลข native/wasm มาจากการรันคนละครั้งบนเครื่องที่แกว่งได้ จึงเทียบกันตรง ๆ ไม่ได้ |
| Thai CER (+0.02) | **ผ่าน** บนหน้าไทยสังเคราะห์ 300 dpi (โมเดล `pdfcraft/assets/models`, เทสต์ `thai_cer_under_skew` แบบ `--ignored`): 0° = 0.008; เอียง 2° = 0.013 (ปิด deskew 0.928); เอียง 5° = 0.013 (ปิด deskew 1.000) — ส่วนต่าง +0.005 ≤ +0.02; มุมที่ใช้ 1.995° และ 5.001° |
| round trip กล่องคำ ≤1.5 px | **ผ่านที่ค่ามัธยฐาน** (เทสต์ `thai_word_boxes_round_trip_under_skew`, `--ignored`): หมึกอยู่ในกล่องคำ 100% ที่ 2°, 5°, −5°; คำที่อ่านเจอทั้งที่ 0° และเอียง (10 คำ) ระยะห่างจุดกึ่งกลางจากตำแหน่งที่หมุนทำนาย: มัธยฐาน 0.79 / 1.35 / 0.89 px แต่หางยาว p90 = 5.4 / 10.8 / 10.8 px ซึ่งน่าจะมาจากขอบกล่องของตัวตรวจจับที่ต่างกันระหว่างสองรอบ (กล่องระดับบรรทัด ยาวหลายร้อย px) ไม่ใช่ความคลาดของการแปลง — ยังแยกสองสาเหตุนี้ไม่ได้ |
| ยังไม่วัด | 90/180/270 กับภาษาไทยจริง, ช่วง ±15–20° ละเอียด, WASM 400 ms |

ข้อจำกัดที่ทราบ: หน้าทดสอบเป็นสังเคราะห์ (บล็อกแทนตัวอักษร) ยังไม่ใช่เอกสารสแกนจริง

**ปัญหาที่พบและแก้แล้ว**
1. *หน้าแทบว่าง* (รูเจาะ ตรายาง เลขหน้า) ถูก "วัด" มุมหลายองศาด้วยความมั่นใจสูง (เช่น −4.6°, 3.8°, −6.1°) เพราะเกณฑ์เดิมแค่ ≥40 จุดหมึก → เพิ่มเกณฑ์ต้องมีส่วนประกอบคล้ายตัวอักษร ≥30 ชิ้น และ ≥300 จุด: 19 จาก 1,251 หน้าที่ตรวจซ้ำ (519 หน้าน่าสงสัย + 732 หน้าควบคุม) เสียคำตัดสินที่ผิดนี้ ที่เหลือไม่เปลี่ยน
2. *ตัวตรวจทิศจากหมึกอย่างเดียวไม่น่าเชื่อถือ*: 5.3% ของหน้าถูกชี้ว่าต้องหมุน 90/270° (ถูกจริงหลายหน้า เช่นตารางแนวนอนที่สแกนตะแคง) แต่ **ตารางตัวเลขและแบบฟอร์มกว้างที่ตั้งตรงถูกสั่งให้หมุนผิด** (ตรวจด้วยตา: ผิด 3 จาก 8 หน้าที่ axis_ratio 1.5–2.2 และผิด 3 จาก 4 ที่ 1.3–1.45; ไม่มีค่าตัดที่แยกได้ขาด) และหน้าตั้งตรงถูกพลิก 180° (เช่นหน้าที่มีตรา) → ปิด `detect_orientation` เป็นค่าเริ่มต้น (เปิดเองได้) การหมุน 90/180/270° ที่ใช้งานจริงยังต้องผ่านตัวตัดสินด้วยความมั่นใจของ OCR เท่านั้น (ทำแล้วสำหรับ 180° ใน `OcrShot::read`; 90/270° ยังไม่ทำ) ทางผลิตภัณฑ์ไม่ได้ใช้ตัวตรวจนี้อยู่แล้ว (`preprocess` ปิดไว้)

**ที่ยังไม่ทราบ** ไม่มี ground truth ของมุมจริง (ใช้ idempotence + ตรวจด้วยตา ไม่ใช่ความแม่นสัมบูรณ์); ไม่ได้วัด CER/ความมั่นใจ OCR บนสแกนจริงก่อน-หลัง; หน้าที่ข้อความน้อยแต่ผ่านเกณฑ์ใหม่ (เช่น f584 หน้า 1 มุม −3.9° ความมั่นใจ 0.77) ยังเป็นความเสี่ยงต่ำ ๆ
