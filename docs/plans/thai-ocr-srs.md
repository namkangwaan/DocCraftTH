## 0. สรุปย่อ

PDF ภาษาไทยที่ได้จากการสแกนค้นหาและคัดลอกข้อความไม่ได้ เพราะ OCR ของ PdfCraft ต้นทางอ่านได้แค่อักษรละติน และ text layer ที่มองไม่เห็นเก็บได้เฉพาะ WinAnsi ซึ่งจะบันทึกอักษรไทยเป็น `?` ระบบนี้เพิ่มโมเดลรู้จำภาษาไทย (PP-OCRv5 Thai, Apache-2.0) และ text layer แบบ Unicode ลงใน Scan & OCR ▸ Recognize text ใช้ได้ทั้งไฟล์เดียว หลายไฟล์ และผ่านเครื่องมือ automation ส่วนการค้นหา คัดลอก และดึงข้อความไทยต้องถูกต้องทั้งใน PDF ที่ผ่าน OCR และ PDF ไทยที่สร้างจาก Word หรือโปรแกรมอื่น ตัวโปรแกรมเป็น Rust ล้วน ไม่ใช้ network ไม่ panic และผลของหน้าภาษาละตินต้องเหมือนเดิมทุกไบต์ ถือว่าสำเร็จเมื่อ CER เฉลี่ยไม่เกิน 5 % บนชุดสังเคราะห์ ผ่านเกณฑ์บนชุดสแกนจริงที่เก็บในเครื่อง และค้นคำไทยที่อยู่กลางวลีเจอ (เช่น `ประจำ` ใน `รายงานประจำปี`)

## 2. ขอบเขต ผู้ใช้ และข้อจำกัด

### 2.1 ขอบเขต

1. Recognize text ภาษาไทย: ไฟล์เดียว · หลายไฟล์ · ช่วงหน้า · ผ่าน `ocr_recognize`, `ocr_recognize_files` และ `ocr_status`
2. text layer แบบ Unicode ที่มองไม่เห็นและคัดลอกได้ ใช้เฉพาะหน้าที่มีอักษรนอก WinAnsi
3. ค้นหา คัดลอก และดึงข้อความไทย ทั้งใน PDF ที่ผ่าน OCR และ PDF ไทยทั่วไปที่สร้างจาก Word หรือโปรแกรมอื่น (D4)
4. วัดคุณภาพด้วยชุดสังเคราะห์ใน CI และชุดสแกนจริงที่เก็บในเครื่อง (D5)
5. เอกสาร parity คำแปล และการรวม branch

### 2.2 ผู้ใช้

| กลุ่ม | ใช้ทำอะไร |
|---|---|
| **ผู้ใช้แอป desktop ที่ใช้ภาษาไทย** | เปิด PDF สแกน กด Recognize text แล้วค้นหาหรือคัดลอก |
| **เอเจนต์หรือสคริปต์** | เรียกเครื่องมือ automation ผ่าน `pdfcraft-cli run` หรือ MCP (opt-in) |
| **ผู้พัฒนา fork** | ดึงโมเดล รันชุดวัดผล ออกรุ่น |

### 2.4 นอกขอบเขต

- แปลงผล OCR เป็นข้อความที่แก้ไขได้ (parity `ocr.editable-text-output`)
- deskew และ downsample ภาพ
- OCR บน build เว็บ
- ลายมือ และข้อความแนวตั้ง
- train โมเดลเอง (path A) ซึ่งจะเริ่มได้เมื่อ path B ไม่ผ่านเกณฑ์และผู้ใช้อนุมัติเท่านั้น (`2026-10-17-thai-ocr-training.md`)
- ตัดบรรทัดภาษาไทย (พักไว้ ตามแผน `2026-10-17-thai-line-breaking.md`)
- รู้จำตาราง และ layout หลายคอลัมน์ที่ซับซ้อน

### 4.2 สถานการณ์ใช้งาน

**หลัก**
1. เจ้าหน้าที่เปิดหนังสือราชการที่สแกนมา หน้าจอเป็นภาษาไทย เปิด Recognize text แล้ว dialog เลือก `ไทย` ไว้ให้ กดเริ่ม เห็น progress เสร็จแล้วค้น `ประจำ` เจอ และคัดลอกได้ข้อความไทยที่ถูกต้อง (PR-2, PR-4, PR-5)
2. เอเจนต์เรียก `ocr_recognize_files` ด้วย `{"language":"th"}` กับโฟลเดอร์ 50 ไฟล์ ได้สำเนาที่ค้นหาได้ และรายงานรายไฟล์ (PR-3)
3. ผู้ใช้เปิด PDF ที่ export จาก Word ภาษาไทย ค้น `น้ำ` เจอทั้งที่ไฟล์เก็บเป็น `น้ํา` (PR-5, PR-6, D9)

**รอง**
4. เครื่องที่ไม่มีโมเดลไทยแต่มีโมเดลอังกฤษ เมื่อเลือก `ไทย` ได้ข้อความที่บอกชื่อโมเดลที่ขาด ภาษาอังกฤษยังใช้ได้ (PR-1, PR-2)
5. PDF มีข้อความที่ดึงออกมาเป็นรหัส PUA ทั้งหน้า ระบบบอกว่าข้อความในหน้านี้ใช้ไม่ได้ และเสนอให้ OCR เมื่อผู้ใช้ยืนยันจึงทำ (PR-6, PR-2, D11)
6. ผู้พัฒนารันชุดสแกนจริงในเครื่องก่อนออกรุ่น บันทึก CER ลง board ไม่ commit ไฟล์ (PR-7)

## 13. อภิธานศัพท์

| คำ | ความหมาย |
|---|---|
| **OCR** | การรู้จำอักขระจากภาพ (Optical Character Recognition) |
| **text layer ที่มองไม่เห็น** | ข้อความโหมด render 3 (`3 Tr`) วางทับภาพสแกน ให้ค้นหาและคัดลอกได้ |
| **CER** | Character Error Rate · ระยะ Levenshtein เป็นอักขระ หารด้วยความยาวของข้อความเฉลย |
| **CTC** | Connectionist Temporal Classification · วิธีถอดผลของโมเดลรู้จำเป็นข้อความ |
| **detection / recognition** | หากรอบบรรทัดข้อความ / อ่านอักขระในกรอบ |
| **WinAnsi** | encoding 8 บิตของฟอนต์มาตรฐานใน PDF ไม่มีอักษรไทย |
| **Type 3 font** | ฟอนต์ที่ glyph เป็น content stream ใน PDF ระบบนี้ใช้แบบที่ไม่วาดอะไร |
| **ToUnicode CMap** | ตารางใน PDF ที่ map รหัสอักขระไป Unicode เพื่อให้ค้นหาและคัดลอกได้ |
| **ActualText** | ข้อความแทนที่ใน marked content ที่ใช้ตอนดึงข้อความ |
| **PUA** | Private Use Area (U+E000 ถึง U+F8FF) ฟอนต์ไทยรุ่นเก่าใช้วาง glyph ของวรรณยุกต์ที่เลื่อนตำแหน่ง |
| **NFC** | Unicode Normalization Form C |
| **oracle** | โปรแกรมภายนอกที่ใช้เป็นตัวเทียบผลในการวัด ไม่ได้ส่งไปกับโปรแกรม |
| **incremental save** | บันทึกโดยต่อ revision ใหม่ท้ายไฟล์ ไม่เขียนทับของเดิม |
| **`--root`** | โฟลเดอร์ที่เครื่องมือ automation อ่านหรือเขียนได้ |
| **Machine lock** | กฎใน board ว่า cargo หนักรันได้ทีละงาน |
| **P / N / C / D / PR** | pain point · ความเสี่ยงใหม่ · ข้อจำกัด · การตัดสินใจ · กระบวนการ |
| **FR / NFR / Q / S / AC / CR** | ข้อกำหนดด้านการทำงาน · ไม่ใช่การทำงาน · ชั้นคุณภาพ · ภัยและมาตรการ · เกณฑ์ยอมรับ · การเปลี่ยนแปลง |
